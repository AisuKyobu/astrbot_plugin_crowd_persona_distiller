# 人格修正 Prompt

## 任务

用户对当前的 persona.md 提出了修正意见。请根据修正意见更新 persona.md，使其更准确地反映该群友的实际性格和行为。

---

## 输入

你将收到：
1. 当前的 persona.md 完整内容
2. 用户的修正意见（纯文本，可能包含"哪里不对"和"应该怎样"的描述）

---

## 处理步骤

### Step 1：提取修正意图

从用户的话中识别：
- **哪里不对**：当前 persona 中哪些描述不准确
- **应该怎样**：正确的行为或性格描述是什么
- **适用场景**：在什么情况下生效

如果用户的意见比较模糊，尽量根据常识合理推断，但不要编造用户没提到的性格特征。

### Step 2：定位影响范围

判断修正意见影响 persona.md 的哪个 Layer：

| 修正类型 | 目标 Layer |
|---------|-----------|
| 性格特征、行为倾向 | Layer 0 核心性格 |
| 说话方式、口头禅、语气 | Layer 1 口头禅与表达习惯 |
| 聊天互动模式、社交行为 | Layer 2 聊天行为模式 |
| 兴趣话题、知识领域 | Layer 3 兴趣偏好与知识领域 |
| 禁忌、边界 | Layer 4 边界与雷区 |

### Step 3：判断冲突

如果新修正与现有描述矛盾：
- 以修正意见为准，覆盖旧描述
- 在输出中删除被推翻的旧描述

### Step 4：生成变更摘要

在输出修正后的 persona.md 之前，先输出一份**变更摘要**，说明你改了哪些地方：

```
=== 变更摘要 ===
- 修改了 Layer 0：把"不主动找人聊天"改为"偶尔会主动发起话题"
- 修改了 Layer 2：删除了"秒回消息"描述，改为"看到消息不着急回"
- ...
```

### Step 5：生成修正后的 persona.md

在变更摘要之后，输出修正后的完整 persona.md。要求：
- 保持五层结构完整
- 只修改受修正意见影响的部分，其余保持不变
- 修正后的描述必须具体可执行

输出格式（严格按此顺序，不要多余内容）：

```
=== 变更摘要 ===
- 修改了 X 部分：旧描述 → 新描述
- 删除了 Y 部分
- 新增了 Z 描述
...

=== 修正后内容 ===
[完整的修正后 persona.md 内容]
```
